

# 商品パネルの価格管理

複数のHTMLに掲載する商品価格を `data/prices.json` の1か所で管理するための作業フォルダーです。JSONを変更して更新コマンドを実行すると、同じ価格IDを持つすべての掲載箇所へ反映されます。

```text
data/prices.json を編集 → 更新コマンドを実行 → HTMLを確認 → 通常の手順で公開
```

公開するHTMLには価格が直接書き込まれます。閲覧者のブラウザーでJSONを読み込む処理は不要です。`index.html` はサイトのbody部分の断片で、単独で完成したページではありません。

## 1. 必要な環境と初回準備

- Node.js：このプロジェクトでは **v24.14.0** で動作確認しています。他のPCでもNode.js 24系を用意してください。
- UTF-8で保存できるテキストエディター。
- ターミナル：WindowsはPowerShell、macOS・Linuxはターミナルを使用できます。今回の実行確認環境はWindowsです。
- Gitは差分確認・共同作業に利用できますが、価格更新コマンドの実行には必須ではありません。

1. このフォルダー一式を取得します。HTMLだけでなく、`data`、`scripts`、`price-pages.json` も必要です。
2. Node.jsをインストールした場合はターミナルを開き直します。
3. ターミナルで、README.mdがあるフォルダーへ移動します。以下のパスは自分の保存先に置き換えてください。

Windows（PowerShell）：

```powershell
cd "C:\work\todo"
node --version
node scripts/update-prices.mjs --check
```

macOS・Linux：

```sh
cd "/path/to/todo"
node --version
node scripts/update-prices.mjs --check
```

以降の `node ...` コマンドは各OSで共通です。追加パッケージは使っていないため、`npm install`、Webサーバー、APIキー、Excelは不要です。準備後の価格更新はネット接続なしでも実行できます。

## 2. ファイルの役割

| ファイル | 役割・編集するタイミング |
| --- | --- |
| `data/prices.json` | 価格の正本。価格改定時はここを編集します。 |
| `price-pages.json` | 更新対象HTMLの一覧。ページを追加するときに編集します。 |
| `index.html` | 更新対象のbody部分。価格はコマンドで上書きされます。 |
| `scripts/update-prices.mjs` | JSONを検証し、HTMLの価格を更新する処理。通常の価格改定では編集不要です。 |
| `scripts/update-prices.test.mjs` | 更新処理の動作テスト。 |
| `PRICE-MANAGEMENT.md` | 導入時の補足資料。通常の作業手順はこのREADMEを参照してください。 |

初期導入時は `index.html` の92か所を56件の価格データで管理しています。別ページはまだ登録されていません。

## 3. 日常の価格更新

### 手順1：最新の作業ファイルを用意する

共同作業では、編集前にチームの最新ファイルを取得します。Gitを使わない場合は、作業前にフォルダーをコピーしてバックアップしてください。

### 手順2：JSONの価格を変更する

`data/prices.json` を開き、商品名と条件を確認して対象の `price` を変更し、UTF-8で保存します。

```json
{
  "id": "price-200120",
  "name": "サラサクリップホワイト",
  "condition": "サラサクリップホワイト 100本",
  "price": "¥214.6～"
}
```

これはファイル内の商品1件の例です。ファイル全体をこの例で置き換えず、既存の `products` 配列を維持してください。

| 項目 | 意味 |
| --- | --- |
| `id` | HTMLと結び付ける一意の価格ID。通常の価格改定では変更しません。 |
| `name` | 管理用の商品名。変更してもHTMLの商品名は変わりません。 |
| `condition` | 注文数量・加工方法等の管理用メモ。変更してもHTMLの説明は変わりません。 |
| `price` | HTMLに表示する価格文字列。円記号・小数・「～」も含めて指定します。 |

価格には `"¥214.6～"`、`"¥1,234"`、`"¥187.0"` のような文字列を指定します。半角の `¥` と数字を使ってください。全角の `￥`、負数、空欄、HTMLタグ、`税込` などの説明は指定できません。末尾は「～」「~」のいずれか、または省略が可能です。

JSONはキーと文字列を半角の二重引用符で囲みます。コメントや末尾の余分なカンマは書けません。税込・税抜の計算や小数の丸めは行わず、指定した文字列を反映します。

### 手順3：HTMLへ反映する

README.mdがあるフォルダーで実行します。

```sh
node scripts/update-prices.mjs
```

このコマンドは対象HTMLをその場で上書きします。別の出力フォルダーは作りません。更新前には全対象ページと入力データを検証します。

### 手順4：差分と反映状態を確認する

```sh
node scripts/update-prices.mjs --check
```

`--check` は確認専用で、ファイルを書き換えません。JSONとHTMLの価格が一致すれば「確認完了」と表示されます。「変更0ファイル」は一致していることを意味し、エラーではありません。未反映や入力エラーがある場合は終了コード1になります。

Gitを使用している場合は、以下で変更内容も確認します。

```sh
git diff -- data/prices.json index.html price-pages.json
git status --short
```

他ページを更新した場合は、そのHTMLも差分確認の対象に含めてください。Git未登録の新規ファイルは通常の `git diff` に出ないため、エディターでも内容を確認します。

`--check` が確認するのはデータの形式と反映状態です。金額の業務上の正しさ、商品条件、掲載位置、見た目は担当者が確認します。

### 手順5：公開・引き継ぎ

更新されたHTMLのbody部分を、従来どおりCMS等に貼り付けるか、案件の手順で納品・公開します。コマンドは公開先やCMSを自動更新しません。JSONとスクリプトを公開サーバーへ置く必要もありません。

作業者間では、**価格JSONと更新後のHTMLをセットで共有**します。対象ページ一覧を変更した場合は `price-pages.json` も含めます。HTMLの価格だけを直接変更すると、次回実行時にJSONの値へ戻ります。

## 4. 別ページ・新商品を追加する

### 同じ価格を別の掲載箇所にも表示する

対象HTMLで、価格を表示する要素に登録済みの価格IDを指定します。パネルやspanに限定されず、テーブルのtd、div、p、strong、見出しなどでも使えます。

```html
<p class="panel_price-price">
  1本あたり 販売価格（税込）
  <span data-price-id="price-200120">¥214.6～</span>
</p>
```

たとえば、テーブルのセルや強調表示にも同じIDを指定できます。

```html
<table>
  <tr>
    <th>サラサクリップホワイト（100本注文時の単価）</th>
    <td data-price-id="price-200120">¥214.6～</td>
  </tr>
</table>

<div data-price-id="price-200120">¥214.6～</div>
<p>販売価格：<strong data-price-id="price-200120">¥214.6～</strong>（税込）</p>
```

`data-price-id` の値は二重引用符または単一引用符で囲みます。**IDを付けた要素の中身が価格に置き換わります。** 要素自体のタグ・属性と、価格前後の空白・改行は保持されます。タグの種類で価格の扱いは変わりません。

指定先は、明示的な終了タグがあり、中身が価格テキストだけの要素にしてください。`td` や `p` の終了タグも省略しないでください。「販売価格」「税込」等の文言を同じ要素に含めると、その文言も置き換わるため、上の例のようにIDを付けた要素の外へ置きます。

子タグやコメントを含む要素への指定はエラーになります。装飾がある場合は、価格だけを囲む内側の要素にIDを付けてください。

```html
<!-- このように価格を囲むstrongに指定します -->
<td><strong data-price-id="price-200120">¥214.6～</strong>（税込）</td>
```

`img`・`input`・`br`等の終了タグを持たない要素や、`script`・`style`・`textarea`・`title`・`template`自体には指定できません。画像のalt属性や入力欄のvalue属性を更新する機能ではありません。コメント内やscript等の文字列中に書かれたHTMLの例も更新対象外です。

新しいHTMLファイルを追加した場合は、`price-pages.json` にも登録します。

```json
{
  "pages": [
    "index.html",
    "pages/ballpen.html"
  ]
}
```

この例の `pages/ballpen.html` は説明用です。実際に存在するファイルを指定してください。パスはプロジェクトからの相対パスで、区切りには `/` を使います。指定できるのはプロジェクト内の `.html` ファイルです。未登録のページは更新されません。

追加後は更新コマンドと `--check` を実行します。IDのない価格がすべて自動検出されるわけではないため、新しいページを追加するときは、パネル・テーブル・本文等に掲載する価格要素を漏れなく確認してください。

### 新しい商品・価格条件を登録する

1. `data/prices.json` の `products` 配列に商品を追加します。
2. 半角英小文字・数字・ハイフンで、重複しないIDを付けます（例：`pen-a-print-100`）。
3. HTMLで価格を表示する要素（td・div・span等）に同じIDを設定します。
4. 必要なら対象ページ一覧を更新し、更新・確認コマンドを実行します。

同じ商品でも、100本注文と1本注文、印刷と彫刻、単価とセット価格など、価格条件が異なる場合は別IDにします。同じ金額やリンク先という理由だけでIDを共通化しないでください。

## 5. 自動更新の対象外と確認待ち事項

自動更新するのは、対象HTMLの `data-price-id` が付いた価格要素の中身です。次の内容は必要に応じて手動で修正します。

- 商品名、注文数量、税込表記、説明文。
- 価格帯別セクション（200円台等）の掲載位置。改定で価格帯をまたぐ場合は移動も必要です。
- バナー画像に描かれた価格、画像のalt属性、送料等の金額。

元サイトのCSS・画像等を同梱していないため、HTMLを単独で開いても本番の見た目は再現できません。見た目は案件のプレビュー環境等で確認してください。

以下は初期移行時の既存表示に差異・条件不明があり、別IDで保持している項目です。記載金額は移行時の値で、正しい最新価格を保証するものではありません。

| 確認する商品 | 移行時の状態・対応 |
| --- | --- |
| プロパス・ウィンドウ100本 | `price-keikopen` は¥209、`price-205210` は¥218.9。正しい価格・条件を担当者へ確認します。 |
| ジェットストリーム | 同じリンク先でも `price-205010-review` は¥577.5~、4&1の `price-205010` は¥920.6~。商品名・条件を確認します。 |
| シャーボX | 種類別の `price-multipen` はモデル不明のため、ST3の `price-203001` と分けています。 |
| クルトガ | `price-sharppen` は¥495、`price-1400000967` は¥495.0。同一条件であることを確認してからID・表示を統一できます。 |

確認後は必要なJSON・HTMLを変更し、この表にも解決状況を記録してください。

## 6. 困ったとき

| メッセージ・症状 | 対応 |
| --- | --- |
| `node` が認識されない／command not found | Node.jsのインストールとPATHを確認し、ターミナルを開き直して `node --version` を実行します。 |
| `Cannot find module` | README.mdがあるフォルダーで実行しているか、`scripts` を含む一式があるか確認します。 |
| `ENOENT` | 指定されたファイルが存在するか、`price-pages.json` のパス・大文字小文字が正しいか確認します。 |
| JSONの構文エラー | 引用符、カンマ、括弧を確認します。コメントは削除してください。 |
| `未登録の価格ID` | HTMLのIDに対応する商品をJSONへ登録するか、IDの入力間違いを修正します。 |
| `価格IDが重複しています` | JSONのIDを一意にします。HTMLの複数箇所で同じIDを使うことは問題ありません。 |
| `商品データの形式が不正です` | ID、空でない商品名、価格文字列の書式を確認します。 |
| `data-price-id の書式を確認してください` | 引用符で囲んだ有効なIDを、1つの要素に1つだけ指定します。 |
| `価格要素には明示的な終了タグが必要です` | 終了タグを記述し、子タグ・コメントを含まない価格だけの要素へIDを移します。 |
| `更新対象にできません` | td・div・span等、終了タグのある表示要素にIDを指定します。 |
| `data-price-id 未設定の価格があります`／`価格IDがありません` | 対象HTMLの価格要素へIDを設定します。価格を持たないページは対象一覧に入れません。 |
| `価格が未反映です` | `node scripts/update-prices.mjs` を実行し、再度 `--check` します。 |
| コマンド成功後も公開サイトの価格が変わらない | ローカルHTMLを公開先へ反映したか、正しいページを更新したか確認します。 |
| 文字化けする | JSON・HTMLをUTF-8で保存しているか確認します。 |

入力エラーはHTMLへの書き込み前に検出します。ただしディスクや権限の問題による書き込み途中の失敗に備え、自動バックアップ機能はないためGitや作業前コピーを利用してください。誤った価格を反映した場合はJSONを正しい値に戻して再実行し、公開済みの場合は修正したHTMLも再公開します。

## 7. スクリプトを変更した場合の確認

```sh
node --test scripts/update-prices.test.mjs
node scripts/update-prices.mjs --check
```

テストは複数掲載の更新、周囲のHTML保持、未知・重複ID、不正価格等を検証します。通常の価格改定では「3. 日常の価格更新」の手順で確認してください。

## 8. Excel・CSVを使いたい場合

現状はJSON入力のみ対応しています。ExcelやCSVを保存しただけでは反映されません。将来CSVへ変更する場合は `id / name / condition / price` を列として入力処理を改修し、管理元を一本化します。JSONとCSVの両方を手編集する運用にはしないでください。
